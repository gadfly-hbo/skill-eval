# 运营数据分析 · 详细方法库

> 本文件由 SKILL.md 正文下沉而来，按需加载，不占正文预算。所有公式与阈值均可直接复算。

## 一、描述性统计

### 集中趋势
- **均值** `μ = Σx / n`：数据近似对称时使用；受异常值影响大
- **中位数**：数据偏态时优先使用；不受异常值影响
- **众数**：分类数据用

### 离散程度
- **标准差** `σ = √(Σ(x-μ)² / n)`：波动幅度
- **四分位距** `IQR = Q3 - Q1`：对异常值稳健，异常检测主力工具
- **极差** `max - min`：只用于快速看区间

### 选型对照表

| 数据形态 | 中心指标 | 离散指标 | 原因 |
|---|---|---|---|
| 对称分布 | 均值 | 标准差 | 均值稳定 |
| 偏态分布（长尾） | 中位数 | IQR | 均值被长尾拉偏 |
| 含极端值 | 中位数 | IQR | 抗污染 |
| 分组对比 | 各组均值 | 组间标准差 | 看差异显著性 |

## 二、趋势分析

| 方法 | 公式 / 参数 | 适用条件 | 禁忌 |
|---|---|---|---|
| 移动平均 | `MA_t = (x_t + ... + x_{t-n+1}) / n`，n ≥ 3 | 短期波动掩盖长期趋势 | n≥ 序列长度的一半会抹平趋势 |
| 线性回归 | `y = β0 + β1·x` | 判断整体方向与斜率 | R² < 0.3 时不得称"趋势明显" |
| 同比 | `(本期 - 去年同期) / 去年同期 × 100%` | 消除季节性 | 基期为 0 或缺失时不可算 |
| 环比 | `(本期 - 上期) / 上期 × 100%` | 反映短期变化 | 对季节性敏感，须与同比同看 |
| 季节指数 | 各期均值 / 总均值 | 识别周期性 | 需 ≥ 2 个完整周期 |

**同环比规则**：只有同时给出同比与环比的结论才叫"趋势"；只有环比时必须标注"未消除季节因素"。

## 三、异常检测

### 方法选择（按分布形态与样本量）

| 情形 | 判定方法 | 阈值 | 前提 |
|---|---|---|---|
| 近似正态、样本 ≥ 30 | 3σ（Z-score） | \|Z\| > 3 | 均值±3σ覆盖约 99.7% |
| 偏态分布、任意样本量 | IQR | 超出 Q1−1.5×IQR 或 Q3+1.5×IQR | 不依赖分布假设 |
| 极端值排查（更严） | IQR 3倍 | 超出 Q1−3×IQR 或 Q3+3×IQR | 只捕极端离群点 |
| 时序突变 | 连续偏离 | 连续 ≥ 3 点超阈值 | 单点异常多来自录入错误 |

### 输出要求（缺一不可）
1. 写出所选方法与阈值（如"3σ 法，|Z| > 3"）
2. 写出具体偏离度数值（如"低于均值 2.3σ"或"偏离度 −24%"）
3. 区分异常性质：**录入错误**（修正后重算）／**真实业务波动**（列入异常清单并给核实动作）
4. 给核实建议与时限，禁止直接删除异常值

### 相关性分析
- **皮尔逊 r**：线性关系，|r| > 0.7 才值得进一步查
- **斯皮尔曼 ρ**：单调非线性、秩次数据
- **硬规则**：相关不等于因果。输出相关结论必须附「未做因果检验，需进一步验证」

## 四、指标拆解（第四段专用）

| 指标 | 拆解式 | 归因读法 |
|---|---|---|
| 销售额 | 客流 × 客单价 | 各自算同比，看谁贡献百分点更多 |
| 利润 | 收入 − 成本 | 按成本科目拆增量来源 |
| 转化率 | 转化数 ÷ 曝光数 | 按渠道/品类分组拆 |
| 复购率 | 复购用户 ÷ 活跃用户 | 拆为留存 × 复购频次 |
| 人效 | 产出 ÷ 人数 | 拆为工时 × 单位产出效率 |

**校验规则**：各项贡献之和须与实测总变动吻合；误差 > 2 个百分点须说明原因（如口径差异、四舍五入、交互项）。

## 五、数据质量五维

| 维度 | 判定标准 | 不合格处理 |
|---|---|---|
| 准确性 | 抽样 20 条复核错误率 < 2% | 标注并修正 |
| 完整性 | 关键字段缺失率 < 5% | 标注缺失，**不插补** |
| 一致性 | 跨系统同名指标口径一致 | 明确以哪套为准 |
| 唯一性 | 主键无重复 | 去重并记录去重条数 |
| 时效性 | 导出时间与分析期间匹配 | 标注导出时间 |

**禁止插补**：缺失值只做标注。用均值/前值填充会制造出不存在的趋势。

## 八、四类数据工程陷阱（对应红线 6–9）

这四类错误的共同点：**数据本身合法、算出来的数字也自洽，但结论从源头就是错的。** 统计方法再精细也救不回来，必须在动手分析前查。

### 9.1 连接爆炸

**症状**：明细行数远多于预期；两张表 JOIN 之后计数与求和同时变大；分组合计超过总数。

**成因**：多对多关系被当成一对多。典型如「订单表 JOIN 促销活动表」——一单命中多个活动，行数按活动数翻倍。

**检测动作**：

```
连接前行数  →  连接后行数  →  比值 = 放大倍数
若比值 > 1 且无合理解释，判定连接关系有误
```

具体三步：
1. 各自单表计数：`COUNT(*)`，记下两边的基数
2. 连接后再计数：与「主表行数」比较，不等即为放大
3. 计数实体时改用 `COUNT(DISTINCT 主键)` 而非 `COUNT(*)`

**预防**：连接前先确认关系是 1:1、1:N 还是 N:M；N:M 必须先聚合到同一粒度再连。门禁 `DT01`/`DT02` 检出重复行与主键重复，是这一陷阱的前置信号。

### 9.2 期间不完整

**症状**：本期数据明显下滑；月度总量在月末自动「回升」；跨期比较的降幅恰好等于已过天数占比。

**成因**：拿进行中的本期比完整的基期。周三看「本周」比上周整周，天然低 60%。

**检测动作**：

```
本期结束日 - 本期起始日 + 1  =  本期已过天数
基期结束日 - 基期起始日 + 1  =  基期完整天数
两者不等 → 禁止直接比总量，须换算日均或截取基期同天数
```

**预防**：期间字段必须是完整区间；无法取完整期间时，比较改用「日均」或「同第 N 天」。门禁 `DT05` 查时间轴缺口，`DT06` 查各期行数与日历天数是否一致。

### 9.3 平均的平均

**症状**：分组算出的均值再求平均，与总均值对不上；小数群体的均值把大盘拉偏。

**成因**：各组样本量不同时，组均值的算术平均 ≠ 加权平均。

**算例**：

| 组 | 样本数 | 均值 | 加权贡献 |
|---|---:|---:|---:|
| A | 100 | 50 元 | 5,000 元 |
| B | 10 | 200 元 | 2,000 元 |

```
错：(50 + 200) / 2 = 125 元
对：(100×50 + 10×200) / 110 = 63.64 元
差错 96%
```

**检测动作**：

```
加权平均 = Σ(组均值 × 组样本数) / Σ组样本数
与「组均值的算术平均」比对，差值 > 5% → 判定存在平均的平均
```

**预防**：一律回原始明细聚合，不使用预聚合的均值再做二次平均。

### 9.4 分母漂移

**症状**：转化率、留存率、流失率在两期之间「显著改善」，但分子几乎没动；同期业务量无明显变化。

**成因**：分母定义改了。典型如「活跃用户」从「近 30 天登录」改成「近 7 天登录」，分母骤减，率值自然上升。

**检测动作**：

```
本期分母定义 ≠ 基期分母定义  →  率值不可比
判据：同期分母绝对值变化 > 30%，而分子变化 < 10%，高度疑似口径变更
```

**预防**：率指标必须写清分子分母，并在两期之间核对定义是否一致；变了就并列两套结果，或回溯重算旧期间。此项无法从数据本身判定（数字都合法），必须读口径说明或主动追问——这正是「首次接触新数据源先问五件事」中第 ⑤ 问的由来。

## 九、门禁校验

交付前必跑：

```bash
python scripts/quality_check.py <报告.md>                      # 六段契约 + 九条红线 + 形态分级
python scripts/quality_check.py --data <数据.csv> --key 门店,月份  # 数据体检：四类陷阱七项检查
python scripts/quality_check.py --self-test                    # 门禁自身自测（报告层 + 数据层）
python scripts/quality_check.py --package                      # 包内文件与三处版本一致性
```

判定标准：返回码 0 为通过；非 0 时报告「红线违规」或「未通过项」必须逐条修复，不得绕过。

**先体检再分析**：数据层未通过时，报告层写得再规范也无意义——错的输入不会产出对的结论。正确顺序是先 `--data` 到全通过，再写报告，最后 `quality_check.py <报告.md>`。

## 十、复算器（数值核验）

`scripts/quality_check.py` 验格式，`scripts/calc.py` **验数字**——两者分工不可互相替代：格式对了不代表数字对。

| 子命令 | 算什么 | 对应本文 |
|---|---|---|
| `decompose` | 乘法顺序剥离 / 加法分解，效应之和须精确等于总变动 | 四、指标拆解 |
| `compare` | 同比环比，含基期为 0 与期间不等长防护 | 二、趋势 |
| `outlier` | 3σ / IQR / IQR3，输出偏离度与所选方法 | 三、异常检测 |
| `weighted` | 加权平均 vs 算术平均，识别「平均的平均」 | 8.3 |
| `period` | 期间天数与等长判定 | 8.2 |
| `ratio` | 率值两期比较，检测分母漂移 | 8.4 |
| `trend` | 回归斜率与 R²、移动平均 | 二、趋势 |

**用法**：

```bash
python scripts/calc.py --list                       列出子命令与入参
python scripts/calc.py --selftest                   跑 24 项自测
python scripts/calc.py decompose --json '{"combine":"product","factors":[...]}'
```

**三条使用纪律**：① 复算器只做算术，不做判断 ② 阈值可传参覆盖，输出回显本次所用阈值 ③ 闭合不过即报错（退出码 3），不输出带残差的结论。

**为什么乘法拆解用顺序剥离**：`effect_i = (A_i − B_i) × Π前序 A × Π后续 B`，望远镜求和恒等于 `ΠA − ΠB`，**闭合是构造性的**，不靠事后配平。比率连乘会保留交叉项，两者相差的正是交叉项，不是算错。
