# 运营数据分析 · Data Analysis

先判复杂度定输出形态，再按「口径 → 趋势 → 异常 → 拆解 → 洞察 → 行动」六段输出可复算报告。每条结论绑定数字、可比基准与判定依据，每条建议落到责任人与时限。

> **没有数据也能先跑一遍**：说「用示例数据试一下」读 `references/sample-data.md` 的 42 家门店样例；说「体检一下我的表」则先查脏数据陷阱再出报告。两种都无需准备文件。

## 一、输入要求

五项缺任一，须在报告首段标「⚠️ 输入不完整」并说明影响：

| 输入项  | 最低要求                            |
| ---- | ------------------------------- |
| 分析目标 | 一句话业务问题，缺失须回问不得自行假设             |
| 数据来源 | 系统名称或文件，含导出时间                   |
| 统计期间 | 起止日期，须含可比基期                     |
| 指标口径 | 分子分母定义、是否含税/含退货                 |
| 样本量  | 记录条数或对象数；< 30 时结论须标「样本量不足，仅供参考」 |

## 二、输出分级与六段契约

**先判复杂度再定形态**，避免用六段回答一个单指标问题：

| 问题类型 | 判断特征               | 输出形态                  |
| ---- | ------------------ | --------------------- |
| 直答   | 单指标取值、单次筛选、事实查询    | 数字 + 可比基准 + 口径一句，不套六段 |
| 归因分析 | 多维对比、趋势归因、异常定位     | 六段全文                  |
| 正式汇报 | 季度/年度复盘、对上汇报、跨部门决策 | 六段 + 方法论说明 + 保留意见清单   |

判据：「多少/是否/有没有」→ 直答；「为什么/哪些/哪里/怎么变」→ 归因；「汇报/复盘/评审」→ 正式汇报。

**六段契约**（后两类必用，顺序固定，缺任一段即不合格）：

```
一、数据口径与质量说明：口径定义、统计期间、来源、样本量、缺失值与去重
二、趋势与结构：同比环比、结构占比变化、分组差异
三、异常识别：异常项 | 偏离度 | 判定方法 | 可能原因 | 核实建议
四、指标拆解：乘法/加法拆到可归因的下级因子
五、洞察结论：每条绑定数据 + 可比基准 + 置信说明
六、行动建议与跟踪指标：建议 | 责任人 | 时限 | 跟踪指标
```

**第四段拆解范式**（指标 = 各因子乘积）：销售额 = 客流 × 客单价；利润 = 收入 − 成本；转化率 = 转化数 ÷ 曝光数。各项贡献之和须与实测值吻合，误差 > 2 个百分点须说明原因。

**口径提示**：销售额 ÷ 客流严格说是「人均消费」；「客单价」= 销售额 ÷ 成交笔数。只拿到客流、无成交笔数时须在报告中注明用的是人均消费口径，不得直接称客单价。

**第六段写法**：每条建议须含「做什么 + 谁做 + 何时完成 + 什么指标验证」四要素，缺一不输出。

**交付形态**：六段全文必须直接回显在回答正文里，不允许「报告已落盘、对话只留一句摘要」。
若同时写入文件，回答中仍须完整包含六段标题、全部结论数据、样本量与责任人时限——回答即交付物，文件是附加副本。
理由：下游读者（含评估工具、转发场景、只看终端的用户）不应被迫打开文件才能拿到结论。

## 三、工作流

1. **锁定口径**：确认分子分母、期间、币种、是否含退货，先定口径再算
2. **清洗数据**：去重、统一单位、缺失值**标注不插补**（插补会伪造趋势）
3. **查陷阱**：过一遍第四节四类陷阱，命中先修正再算
4. **描述与对比**：均值/中位数/标准差 + 同比/环比/分组对比
5. **检测异常**：3σ（正态、样本 ≥ 30）或 IQR（偏态、小样本），写明所选方法
6. **拆解归因**：乘法或加法拆到下级因子，校验贡献之和
7. **验证与成文**：换口径复算；跑 `scripts/quality_check.py` 校验结构与格式，跑 `scripts/calc.py` 复算数字

## 四、核心方法

> 方法库（统计公式、阈值、图表选型、四类陷阱的检测动作）见 `references/methods.md`。>
> 理论与出处见 `references/theory.md`；完整样例见 `references/examples.md`；示例数据见 `references/sample-data.md`。

- **描述与对比**：均值/中位数/众数、标准差、IQR；同比、环比、横比、纵比
- **趋势**：移动平均（n ≥ 3）、线性回归斜率、季节指数
- **异常**：3σ 法 |Z| > 3；IQR 越界 Q1−1.5×IQR ~ Q3+1.5×IQR
- **相关性**：皮尔逊 r、斯皮尔曼 ρ，|r| > 0.7 才值得进一步查
- **可视化**：趋势折线、对比柱状、占比饼/环、分布直方/箱线、关系散点

**四类数据工程陷阱**：连接爆炸（多对多 JOIN 放大行数）、期间不完整（进行中的本期比完整基期）、平均的平均（组样本数不等时算术平均≠加权）、分母漂移（率指标分母定义变了）。检测动作见 `references/methods.md` 第八节，逐条对应红线 6–9。

## 五、专业红线

**硬禁止（违反即输出作废）**：

1. 禁止无依据的量化预测——除非写出假设、基准与测算过程
2. 禁止把相关当因果——相关结论须标「未做因果检验，需进一步验证」
3. 禁止口径缺失下结论——无口径声明的数据不可复算
4. 禁止用插补数据支撑趋势结论——缺失值只标注不填充
5. 禁止输出无责任人的行动建议
6. 禁止 JOIN 后不核行数——放大即判定连接关系有误
7. 禁止期间不等就比——须等长或按同天数对齐

   补充纪律：涉及天数比例的表述必须自己算一遍。写「降幅 ≈ 1 − 天数比」这类等式时，等号右边要真是那个数
   （例：本期覆盖 53.6% 天数，则 `1 − 53.6% = 46.4%`，不能写成 `≈ 1 − 53.6%` 后不给出 46.4% 而让读者自行脑补）。
   宁可写「本期天数仅为基期的 53.6%，观测到的 −50% 降幅与之接近，几乎完全由日历天数差造成」，也不要写可能算错的等式。
8. 禁止对已分组均值再求平均——样本数不等须回原始数据加权
9. 禁止分母变更后直接比——须先确认两期分母定义一致

**软护栏**：样本量 < 30 或分组 < 5 个对象时结论须标置信度不足；异常值不得直接删除，须先区分「录入错误」与「真实业务波动」。

## 六、能力边界

**✅ 可做**：数据清洗与口径对齐；描述统计与同环比；异常检测与偏离度量化；指标拆解归因；四类陷阱体检；按契约出报告并通过门禁。

**❌ 不做**：修改业务数据或代做决策；输出预测值与业绩承诺（须专业预测模型）；替代审计、税务申报与法律判断；样本不足时给确定性结论。

**首次接触新数据源先问五件事**（问不清就不算；问到的口径写入报告第一段，下次直接复用）：

① 「客户/门店/用户」指哪一层，中间隔几层？
② 唯一标识是什么，同一对象有多套 ID 吗？
③ 最常被问的 2–3 个指标，公式与取数表是哪个？
④ 永远要排除哪些记录（测试单、内部账号、已关店、已退款）？
⑤ 新人最容易在哪一步算错？

## 七、质量检查清单

- [ ] 五项输入已确认；输出形态与问题复杂度匹配
- [ ] 六段齐全且顺序正确（或已判定为直答并说明理由）
- [ ] 异常写明判定方法与偏离度；拆解贡献之和误差 ≤ 2 个百分点
- [ ] 四类陷阱逐条排查：连接行数、期间天数、均值加权、分母定义
- [ ] 每条洞察绑定数字与基准；每条建议含责任人与时限
- [ ] 涉及计算的部分已用 `scripts/calc.py` 复算，拆解效应之和精确闭合（差额 ≤ 0.01）
- [ ] 九条硬红线未触发；已跑 `quality_check.py` 返回码 0

**两个脚本分工**（不可互相替代：格式对了不代表数字对）：

| 脚本                         | 管什么                                       | 用法                                               |
| -------------------------- | ----------------------------------------- | ------------------------------------------------ |
| `scripts/quality_check.py` | **验格式**：六段契约、九条红线、输出形态分级、四类陷阱体检           | `--data` 体检数据、`--self-test` 自测、`--package` 查包一致性 |
| `scripts/calc.py`          | **验数字**：拆解对账、同环比、异常检测、加权平均、期间对齐、分母漂移、趋势回归 | `--list` 看子命令、`--selftest` 跑 24 项                |

**三个最该用它的场合**：

1. **第四段拆解**——`decompose` 用顺序剥离，效应之和构造性精确等于总变动，不必事后配平；同时给出占基期百分点与比率校验，交叉项差异一目了然。
2. **报数被追问时**——每个子命令都回显算式（`客流效应 = (1,112,500 − 1,250,000) × 80 = -11,000,000`），可当场抄给提问者核对。
3. **两期比较前**——`period` 判等长、`ratio` 查分母漂移。这两类错误算出来数字自洽但结论从源头就错，事后无法察觉。

**纪律**：复算器只做算术不做判断；阈值可传参覆盖；闭合不过直接报错（退出码 3），不输出带残差的结论。

## 八、使用示例

**示例 1**：连锁门店 12 个月销售额、客流、客单价，问利润为何下滑。
→ 按「销售额 = 客流 × 客单价」拆解，同比 −6% 中客流贡献 −11 个百分点、客单价 +5 个百分点，主因是客流而非定价；IQR 法锁定 3 家客流下滑超 20% 的门店（−24%/−22%/−21%），给出核实动作与时限。

**示例 2**：3 月与 4 月日活跃用户表，判断有无异常。
→ 声明口径与样本量（日粒度 61 条），标记 4/12–4/18 连续 7 天低于均值 2.3σ（3σ 法），提示该时段同时是埋点版本切换窗口，须先排除口径变化再判异常；不输出预测。

**示例 3**：贴一张表说「帮我看看这数据能不能用」。
→ 走体检形态，逐项给「检出/未检出 + 依据数字」：查重复行（主键唯一否）、查时间轴（月份有无缺口）、查连接（明细与汇总对得上否）、查分母（两期口径一致否）、查各期天数（2 月与 3 月不可直接比总量），再决定是否出六段报告。

## 九、职责边界

- 只做统计、拆解与体检，不做流程建模（归 process-mapping）、不做方案设计（归 optimization-plan）
- 财务口径相关结论须交财务技能复核，本技能不替代审计
