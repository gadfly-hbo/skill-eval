# 测评器开发规范

适用于 Skill、Tool、Prompt 及其他 Agent 能力和组件测评器的开发、验收与交付。各项目按本规范冻结任务、判据和执行范围，分别验收测评器的正确性与被测对象的效果。以 `skill-eval/docs/测评器开发规范.md` 为维护底稿，各 eval 目录保留同版副本。项目特有的指标、阈值和执行范围写入各自的建设方案与冻结计划。

## 一、四条开发原则

1. **Host 管环境。** Host 负责模型与依赖身份、工作目录、网络和文件权限、凭证、授权、用量和证据。用实际访问探针核对候选、评委及其子进程可用的资源，验证隐藏真值、凭证及其他侧原始工作区不可达。遇终态 Host 故障时按影响范围停止派发并保全证据。
2. **Agent 自主执行。** Agent 在授权内决定方法、工具、步骤和纠错。模型使用已核验的原生输入输出能力。题数、每侧重复次数和评委轮数定义实验规模，额外的超时、预算或其他执行限制按项目契约及用户授权确定。
3. **优先复用第三方 SDK 已有能力。** 通过官方公开接口复用会话、工具、流式事件和恢复机制。自有 Host 处理隔离、授权和取证，测评器处理配对与计分。未经授权不得直接改造第三方 SDK，升级须经授权并使用官方版本。
4. **减少人类的操作。** 正式测评、冒烟和离线端到端测试共用主执行路径，回放复用计分和报告。Host 自动做环境核验、留痕和交付。只在未确定的选项会改变执行范围时询问，一次收集独立选项，复用用户已经给出的选择。

## 二、开发与交付流程

| 阶段 | 要做的事 | 完成条件 |
| --- | --- | --- |
| 1. 定义契约 | 写清要支持的决策、被测对象、场景、对照条件、独立样本和判据。区分单体契约验证与对照增益验证。 | 另一人能按计划判定通过、失败或证据不足。 |
| 2. 准备与冻结 | 准备独立任务、私有真值、正负控、执行矩阵、随机化、成本估算和停止规则。冻结候选、输入与计分规则。 | 看结果前能从清单还原每个计划项的条件和判据。 |
| 3. 实现与离线验收 | 先用固定样本验证计分，再经正常入口检查编排、隔离、故障收尾和报告。按第四节验证，记录源码与依赖身份。 | 正反例符合预期，失败与未运行可区分，报告可从原始记录复算。 |
| 4. 按授权验证真实链路 | 新入口或真实依赖行为变化时，获授权后用最小案例冒烟。需要正式测评时，另建运行并执行冻结矩阵。文档、离线判据或报告改动按影响范围验证，记录真实证据的适用范围。 | 冒烟可核实实际版本、调用、隔离、终态、计分和用量。未执行的验证明确标为未验证或不适用。 |
| 5. 复核与交付 | 对照清单核对全部计划项并复算关键指标。计分、隔离、证据身份等高影响改动交独立复核，交付时核验合入内容。 | 交付版本与验证对象一致，记录失败、未验证项和证据路径，分别记录合入、发布与实际采用。 |

轻量改动可把计划、验证和结论放在一份记录中。修复时先从原始证据定位归属，区分测评器、题集、宿主工作流和候选本身，再用离线夹具复现、最小修复、同条件回归。涉及计分或结论变化时，说明新旧差异和适用范围。

最小配对冒烟通常用公开单题，两侧各一次，按判据决定是否加一轮盲评。正式测评按任务覆盖和结论需要确定规模。配置档位时展示题数、每侧重复次数、评委轮数及预计会话数，消融独立选择。以用户确认后的执行矩阵核对派发和报告。

### 冻结清单的最少信息

- **对象与输入。** 记录候选和基线版本、完整有效载荷的哈希、任务及来源、最终消息或工具配置、数据和环境初始状态。模板、引用文件和工具 schema 按实际加载内容纳入身份。
- **执行。** 记录测评器提交与实际执行源码指纹、SDK 包版本及入口身份、精确 `provider/model`、运行参数、授权范围、任务和会话矩阵、评委身份与匿名顺序。纳入运行中加载的 worker 和解码器等关键组件。可控随机过程记录种子或分配结果。
- **计分。** 记录规则、真值、评委提示和聚合版本，独立样本单位、预定分母、判定阈值、失败归属、可接受的输出等价形式和证据不足时的处理方式。
- **留痕。** 记录运行 ID、父运行或计划 ID、证据路径和访问边界。运行前核验实际身份。使用独立检出或固定副本，避免执行中切换共享工作区使后续 worker 加载不同源码。

对照实验只改变事先声明的候选变量。两侧对其余条件保持一致，包括任务、模型、上下文、权限、资源设置和等价的独立初始状态。一次替换多个组件时，把结论限定为组合效果。冻结题集或判据有修订时另存版本并用于新计划。重跑和重算分别生成新记录，关联原运行及原因。

## 三、题集与判分

- **先验评分器。** 用已知正确、错误、边界、缺失和失败样本验证判据。确定性指标覆盖数值正负号、单位、精度、缺字段、空值和等价格式。失败或空输出不能因负向断言未命中而假通过。
- **用正负控查区分度。** 正控检验链路能测到目标行为，负控检验链路能识别无效或误触发。控制和诊断样本另报，正控失败时明确限制对应结论。消融按测评目的选用，事先冻结移除的能力及保留条件。身份或证据不可比时保留结论不足。若要把改善归因于被移除的契约，原版须分别优于基线和消融版，并满足事先冻结的核验规则。
- **分开量结果与过程。** 激活、工具选用、调用成功、最终任务正确性、用户可见格式、状态副作用与成本分别取证。文本自述不能替代工具轨迹或独立状态读回。内容正确与格式合规各自给结论。
- **客观规则优先。** 稳定的结构、数值和业务状态使用可复算规则。主观质量使用独立盲评，向评委提供任务、评分标准和匿名输出，按计划随机化或换位。格式纠错保留首答和后续回答，同一预定评委轮至多计一票。冲突时按事前约定处理并记录分歧。
- **按独立样本推断。** 同题重复用于观察波动，同题多断言用于拆解行为。把同源、改写或共享场景的题按预定簇聚合。报告实际独立样本量、覆盖率、效果量与适用的区间或判定依据。证据不足时保留该结论。
- **完整对账。** 报告总计划数、成功、失败、未运行和不可判定。已计划失败按冻结规则处理，`NOT_RUN` 保留未执行身份。分列全量记录与计分子集、原始评委结果与规则纠偏结果、观察分母与计划覆盖率。断言条目累计通过率可用于诊断，任务等权配对增益按冻结方法计算。

## 四、实现与离线验证

| 验证面 | 最少检查 |
| --- | --- |
| 计分与报告 | 覆盖好坏样本、等价格式、格式错误、空输出和缺失数据。用同一份固定样本对照新旧结果，核对分母、原始与纠偏结果、证据引用。 |
| 主执行路径 | 从用户实际使用的入口加载夹具，核对候选、对照条件、档位、消融选项、重复和评委分配，检查运行矩阵与产物是否一致。离线环境用假凭证、假响应或本地替身，禁止真实外网请求。 |
| 环境与隔离 | 验证预期文件和工具可用、越界访问被拒绝，隐藏真值、私有断言、凭证和其他侧原始工作区不可达。单列本地模型可解析与远端鉴权、权限和计费是否实际验证。 |
| 失败与恢复 | 注入普通工具错误后恢复、样本终态失败、确认配额耗尽、主动中止、隔离失效、身份漂移与持久化失败等适用故障。核对派发次数、首因和次级错误、失败与未运行矩阵、原始记录、账本和报告。 |
| 长流与大批次 | 涉及流式留痕、账本或持续累积数据时，覆盖长流、大事件和异常退出，计量累计序列化及写入字节相对原始载荷的上界，并逐条读回核对内容、顺序和数量。 |

可恢复的工具或模型交互错误交给 Agent 和 SDK。单样本终态失败时按冻结规则记录，并继续能独立执行的样本。确认不可恢复的配额耗尽、身份或隔离失效、证据无法持久化或收到用户中止时，停止受影响范围的派发，保全首因、已发生记录和未运行项。限流状态码单独出现时按 SDK 的限流处理策略执行。未知用量标为未知，清理错误另记。

流式证据增量追加，每条事件只为日志序列化并写入一次，完整汇总在收尾时生成。长流回归用计量 sink 或隔离文件系统验证多个规模下的累计序列化与写入字节相对原始载荷体积线性增长，并覆盖写入失败和异常退出，逐条读回核对内容、顺序和数量。区分实际计量、推算和未测。强制退出后以已完整写入且可读回的记录为准。 [事件留痕写入放大事故复盘](https://github.com/gadfly-hbo/skill-eval/blob/7c25d33fb186648568646f72f9d92d5a00630d33/docs/开发事故复盘-事件留痕写入放大-2026-11-07.md)

离线验收记录写明实际命令、源码与题集指纹、测试通过数、失败数和跳过数。对未覆盖的真实鉴权、模型权限、计费、宿主交互和候选效果分别标明状态。CLI 能发现技能只证明离线发现成功。

## 五、不同对象的取证重点

| 对象 | 先验证 | 再验证 |
| --- | --- | --- |
| Skill | 冻结整包和实际加载文件，核实基线未加载候选，候选侧具备可查的读取或激活证据。 | 对照输出质量、约束遵守、误触发和成本。把被读取与带来增益分别报告。 |
| Tool | 冻结工具实现、schema、描述、权限和测试数据。直接调用验证参数、返回值、错误语义、超时重试及真实状态变化。 | 若目标是 Agent 工具使用，再单独对照选用、传参、调用顺序、恢复和用户任务结果。两侧状态独立重置。 |
| Prompt | 冻结模板与各侧最终渲染消息，核对角色、顺序、变量、上下文和工具条件。覆盖缺失字段和指令冲突。 | 比较任务正确性、交付格式、红线和成本。先定义允许的等价输出，剩余语义质量交由盲评。 |
| Agent | 冻结任务、初始环境、工具权限、运行配置和目标状态。为多步任务准备可独立读回的结果。 | 同时核对终态和实际交付，按任务要求检查权限、关键轨迹、恢复与副作用。 |
| Extension | 冻结扩展包、SDK、Runtime 模式与配置，先验静态包契约。 | 在获准的隔离 Runtime 核对公开注册、生命周期和 Host 组合兼容。 |
| Guardrail | 冻结合成身份、权限、审批范围和预期策略。 | 分开取证 Agent 遵循和 Host 强制控制，核对允许、拒绝、误拦及实际副作用。 |
| Memory | 冻结记忆来源、版本、权限和有效期，核对 Host 检索与过滤。 | 单列 Agent 的选择、正确使用与隔离。自动注入时，主动检索维度标为不适用。 |
| Script | 冻结源码、运行时、依赖及测试数据，隔离直跑验证退出码、结果与副作用。 | 分别报告脚本本体与 Agent 生成或调用链路。 |
| Subagent | 冻结父子会话的权限、委派契约和任务依赖，复用已有编排。 | 核对交接、故障恢复、结果回流和最终综合，分别报告模拟与真实协作。 |

**Tool 例子。** 用可重置的测试服务验证「幂等创建工单」。模拟首次请求已落库但响应超时，重试后独立读回仍只有一条。越权参数应留下拒绝证据，服务状态保持一致。若还要评估 Agent 是否正确使用工具，另外冻结 Agent 的任务、模型和工具条件进行对照。真实业务写入需单独授权。

**Prompt 例子。** 比较两版「从订单文本提取 JSON」模板。保持输入、模型、工具条件和非候选消息一致，分别冻结最终消息。覆盖普通订单、缺字段、嵌入冲突指令三类场景，按字段真值、JSON 格式和权限红线分别判定。

## 六、运行记录和结论

原始证据按运行 ID 保存，至少能定位到任务、侧、尝试和评委轮次。保留输入指纹、调用与事件、输出与状态读回、计分、失败首因和用量。冻结包、隐藏真值、凭证及敏感原始证据留在私有边界。公开报告与机器清单只发布可共享材料，日志和报告不得包含凭证。

报告先交代回答了什么问题，再给出候选和执行身份、所选档位与消融配置、计划与实际覆盖、各项指标及分母、重要失败和分歧、已知费用与未知用量、可复核证据及结论适用范围。费用估算、Provider 返回的用量和实际账单分别标注。旧报告保留原判据，重算结果另存并关联来源。

按证据层级签署结论。离线验证说明计分、编排或边界在夹具条件下可复现。真实冒烟说明实际入口和依赖在最小场景跑通。候选结论需要与冻结契约匹配的证据。Tool 本体可以用本地直接调用验证，真实 Agent 使用效果需要对应的真实运行记录。用户报告引用正式计分或核验结果，工作区产物等补充诊断单列并标明输入。 [极简真实测试与复测收尾](https://github.com/gadfly-hbo/skill-eval/blob/7c25d33fb186648568646f72f9d92d5a00630d33/docs/data-analysis-1.9.0-极简真实测试与复测收尾-2026-11-07.md)

## 七、decision-review 的五类回归

| 优先级与归属 | 发现的问题 | 离线回归要点 |
| --- | --- | --- |
| 1. 测评器 · 停批与收尾 | 套餐配额耗尽与普通限流需要不同的处理，收到中止信号时也要落下终态。 | 模拟 MiniMax 确认的 `429/2056`，验证只发出首个请求并保留原始错误、未知用量及待执行项。模拟普通 429 和工具错误后恢复。注入 `SIGTERM`，验证失败与未运行项、账本和报告。 |
| 2. 测评器 · 诊断归因 | 误触发题未读取 Skill 符合预期，答错或断言误判容易被误归为漏触发。 | 对同一诊断失败分别提供实际读取和未读取的轨迹，只有前者判误触发。两者都保留断言明细。 |
| 3. 测评器 · 计分与消融 | 全量对与计分对、原始评委与规则纠偏、条目通过率与任务等权增益容易混报。消融核验还需比对实际执行身份。 | 固定计分、诊断、缺失与分歧样本，逐项对账。身份漂移时核验应为结论不足。原版与消融版持平时，该断言不支持契约归因。 |
| 4. 题集 · 数值断言 | 最终金额前有千分位计算式时，断言可能取到算式操作数。 | 用裸答案、带公式和单位的正确结果、错误结果及不完整答案检验提取规则。另存 v2，保留 v1 原件和历史判定。 |
| 5. Qoder · 启动与交付 | 档位和消融应独立选择，新计划与旧冻结计划应分别选题集，消融结论需引用正式核验。 | 检查两项独立选择、已给选项的复用和兼容版本规则。新计划选匹配的最新版，历史计划按原版本与哈希。检查交付引用 `verify` 的 JSON 状态、退出码和两组运行 ID，工作区补充诊断单列。 |

该修复以 `npm run check` 完成类型检查，517 项离线测试通过，0 失败、0 跳过。数字属于该修复版本。原冻结题集、运行记录与历史结论保留，v2 的真实区分度未复测。Qoder 的历史验证覆盖双问题配置结构和离线技能发现，实际会话交互未验证。 [decision-review 修复与验证记录](https://github.com/gadfly-hbo/skill-eval/commit/7c25d33fb186648568646f72f9d92d5a00630d33)
