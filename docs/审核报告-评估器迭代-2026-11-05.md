## 提交一 `b5c4f31`：评委标签一致性校验

### 重点核查 1：分层设计是否正确 —— **正确**

`parseJudgeResponse()` 只忠实记录（`labelConflict: null`），校验集中在 `reconcileJudgeRun()`，这是唯一正确的设计：

- 评委标签的实际语义是「分数更高的那份更好」（反轮 A=skill 95 / B=baseline 58 返回 `win` 可证）
- 前向轮两种语义重合；反向轮分道扬镳
- **实测验证**：把校验放进解析层会把反轮的正确判定误报为「评委自相矛盾」

七项边界手工验证全部正确：

| 边界 | 结果 |
|---|---|
| tie 标签 + 分差 15 | 纠正为 win，记 conflict ✅ |
| tie 标签 + 分差 2（容差内） | 不动 ✅ |
| win + 分差 +25（方向一致） | 不动 ✅ |
| not_judged + 任意分差 | 不动 ✅ |
| 分差缺失 | 不动 ✅ |
| **反轮 A=95/B=58 返回 win**（关键抗误报案例） | 换算后 delta=+37 与标签一致，**不误报** ✅ |
| 正轮 loss + 分差 +25（原始缺陷案例） | 纠正为 win，记录说明 ✅ |

`flipScores` 只翻分数不翻标签——标签方向完全交给分差判定，这个组合没有漏掉边界。tie 但分差大时按方向纠正为 win/loss 是**正确选择**：分数是评委更结构化的输出（受 JSON schema 约束），比自然语言标签可信。

阈值 10 的依据（4 条 tie 分差 ±1~2 属合理容差）与实测数据吻合。

### 重点核查 2：超时 300s —— **合理但未验证**

依据是间接的（反轮 1338 events 思考后空输出）。300s > 被评模型最长 317s 的量级合理，且加了 `--judge-timeout` 可调。**遗留**：新跑一轮才能确证，建议下次评估留意 5.4 节与「未判定轮次」条数。

### 跑批与重算路径一致性

`judgeAll()` 与 `readJudgeDirs()` 都改走 `reconcileJudgeRun`——正反轮口径统一，无漂移。

## 提交三 `61a686f`：断言过严 vs 真缺陷

### 重点核查 1：重算路径改用当前套件重新评估 —— **正确，不违反可复算原则**

这是审核 prompt 里我最担心的一条，结论是**改动正确**：

- 「报告可从原始产物重算」的承诺依赖的是 `cases/*/output.md` 原文与套件定义——两者都没动
- 沿用旧断言结果的「重算」才是假的：改了套件重算却没反应，等于重算没干活
- `status === "failed"` 时不重算的保守处理正确——「没输出」≠「不合规」
- 验证：用 v1.1 与 v2 两个套件对同一份产物重算，得到两份不同归因——正是「拿新套件重新看这批产物」的预期行为

### 重点核查 2：假失败判据边界 —— **发现真实缺陷并已修复**

审核 prompt 自认「`mustNotMatch` 的等价语义几乎没有实际数据验证过」。实测确认**这个边界确实藏着两处缺陷**：

**缺陷 A（拦截层）**：`mustNotMatch` 声明了 `equivalentPatterns` 却完全不拦截等价写法。
实测：禁「平均的平均」+ 等价写法「avg of avg」，输出只含 `avg of avg` → `passed: true`。
旧实现先测主 pattern，没命中直接放行，等价写法形同虚设。

**缺陷 B（归因层，更严重）**：`mustNotMatch` 失败且 `equivalentMatched=true` 时，
improve.ts 判据不区分 kind，把它归成「断言过严（要改套件）」——
但此时真相是**输出出现了被禁的等价写法，是违反禁令，该改 skill**。归因方向完全反掉。

**修复**（本次审核提交）：

1. `assertions.ts`：`mustNotMatch` 的主 pattern 与等价写法**分别测试，命中任一即 fail**
2. `improve.ts`：假失败判定**仅对 `mustMatch`** 生效（`kind === "mustMatch"` 过滤）
3. 回归测试：4 分支拦截语义 + 归因方向各一，旧测试断言的错误行为已改正

**未触发原因**：现有全部套件（example / v1.1-equiv / v2）都没有 `mustNotMatch` + `equivalentPatterns` 组合，所以历史结论未受影响——复算验证证实 v1.1 与 v2 的归因与修复前逐字一致。但这是个**埋着的雷**：任何人按文档写一条这样的断言就会踩中。

### 重点核查 3：`undefined` 保守归类 —— **正确**

「无信息不等于无问题」的保守立场正确。代价（未声明等价写法的断言仍可能误报）在文档 5.1 节有明示，且 `equivalentPatterns` 定位就是「兜底」。

### 重点核查 4：「至少一次命中即判假失败」 —— **可接受，无需收紧**

时过时不过（att1 命中 att2 没命中）判成假失败确实偏宽，但：
- 命中等价写法说明 skill 契约的表达模型**至少部分落地**，优先改套件放宽措辞是合理的第一步
- 放宽后重跑，若 att2 仍失败会归到「约束不稳」——系统会自我纠正
- 收紧判据（如「全部失败都命中才判」）会把部分假失败漏成真缺陷，方向更糟
