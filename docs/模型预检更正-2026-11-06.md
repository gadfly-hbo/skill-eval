## 后续预检行为

新增 `preflightModels` 与 `preflight` 子命令：

```bash
npm run eval -- preflight \
  --model minimax-cn/MiniMax-M3.1-Flash \
  --judge-model xiaomi-token-plan-cn/mimo-v2.6-flash \
  --home ~/.skill-eval/pi-home
```

它调用当前已安装 Pi SDK 的目录组合接口，先创建禁止刷新与鉴权的模型运行时，再由原生 provider 恢复缓存到内存，最后用严格 `getModel(provider,id)` 查询。仓库没有重写目录合并、时间优先级或自定义模型覆盖算法，也没有使用 CLI 的模糊匹配或 custom-id fallback。

- 子进程由 macOS `sandbox-exec` 拒绝所有网络与文件写入，并禁止读取源 HOME/全局认证文件。环境不携带真实凭据；认证和持久存储接口调用即失败。未进入 `runtime.refresh/getAvailable/checkAuth`。
- 只输出指定型号的身份摘要，不输出配置、headers 或原始 SDK 错误。URL 私密部分脱敏并标记 `baseUrlRedacted`，不以脱敏摘要冒充完整远端路由验证。
- 完整 `provider/id` 必须精确存在；裸型号、近似型号、错误 provider、大小写变体及缺失评委均阻断。显式参数缺值不回退到环境或被评模型。
- 非法配置/缓存、SDK 查询异常或缺少隔离后端均失败关闭，不回退为扫描缓存或未隔离查询。目前只支持 macOS 隔离后端。
- `eval` 在创建运行目录、冻结候选及调用模型前检查全部矩阵模型和评委；已有非空目录仍优先拒绝覆盖。`runEvaluation` 内核行为保持原样，冻结运行调用者应显式消费这份预检结果及外部更正记录。
- 工作流环境脚本也调用该检查，失败不能输出 `PREFLIGHT_OK`。该环境脚本原有复制配置/清理锁逻辑仍保留；本次实机检查只运行只读 `preflight` 命令，没有运行环境准备脚本去覆盖本机配置。

CLI 模型选择沿用原优先级：被评 `--models`/`--model` 优于 `SKILL_EVAL_MODEL`；评委 `--judge-model` 优于 `SKILL_EVAL_JUDGE_MODEL`，未指定时沿用被评模型；`--home` 优于 `SKILL_EVAL_PI_HOME`。工作流脚本在未给定参数/环境时继续使用既定 MiniMax/MiMo 默认值。
