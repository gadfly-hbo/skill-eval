# 事件留痕写入放大事故复盘

2026-11-07，data-analysis 1.9.0 两题真实业务案例因 Host 资源故障中止。受影响控制器及 worker 已停止，失败材料完整保留；该运行不作为完整评测或 v0.3.2 发布通过证据。

## 根因与漏测

`controlled-session.ts` 每收到一个事件就同步序列化全部累计事件，并覆盖 `events.partial.json`。该实现随历史增长产生平方级重复工作。Codex 的短流功能测试漏测累计序列化和写入成本，是实现及验证设计失败。

故障样本保存 7,722 条事件，文件 28,588,078 字节。按冻结故障源码和实际事件长度逐项重建，累计应用层序列化/写入载荷约 95.09 GB，为最终文件的约 3,326 倍。重建仅进行长度计量与算术求和，未再次写入这些前缀。该数字不是 SSD 物理写入或磨损测量。

最后一次 Provider 响应已以 `end_turn` 完整结算，Host 事件转发及收尾尚未完成，不能归咎于模型持续思考或工具死循环。普通工具错误允许 Agent 自主纠错的规则保留。

## 最小修复与离线验证

每条事件只序列化自身，追加至 `events.partial.jsonl`；会话结束后仍由原 runner 一次生成 `events.json`。追加失败记录 `EVENT_EVIDENCE_WRITE_FAILED`、事件索引及 `persistence_error`，停止后续请求。未新增编排、SDK 改造或命令分类器。

- 旧实现 RED：128 条模拟流式 delta 产生 276 条原始事件，累计尝试写入 25,056,445 字节，最终事件数组 179,209 字节。计数 sink 阻止旧路径实际重复写盘。
- 修复 GREEN：10,001 条模拟 delta 产生 20,022 条原始事件，实际追加 12,104,924 字节，最终数组 12,104,925 字节；逐行读回与全部收到的事件在内容、顺序、数量上完全一致。
- 新增 5 项回归：128 / 10,001 delta 字节上界与完整性、磁盘追加失败、Provider 断流、真实原生 worker SIGKILL。骤停测试验证已收到的完整记录，不保证 Host 本身被杀死或系统掉电时未落盘的数据。
- `npm run check` 类型检查通过，463/463 测试通过，0 失败、0 跳过。标准离线入口清除真实凭证并阻止真实网络；测试使用内存假响应。本次修复验证没有真实 Provider 调用。
