## 首次失败取证

每个新会话在模型不可读写的父控制目录保存 `failure-evidence.json`，并将快照保存在 session 结果中。文件原子更新并同步落盘；已有文件冲突或取证写入失败会停止执行，不覆盖既有证据。

首次失败记录稳定错误码、事件类型、工具 ID／名称、结构化退出码及完整事件数组中的零起始索引。后续 worker 级联错误、并发工具中止和助手中止另存为次生事件，不替换首因。取证元数据不保存工具参数或原始输出；完整原始事件仍单独保留。

对于原生 bash 最终退出 0、但输出含权限拒绝的复合命令，只保存“成功输出中出现拒绝文字”的非权威观察，不新增 fatal 判断。正常读取的源码或文本含 `aborted`、权限词不会因此触发停批；原 `isError` 判断保持不变。

对旧失败只做了新取证器的离线事件解析：首因是 **事件索引 359，bash，退出码 1**；索引 220 的退出 0 拒绝信息是观察项；索引 362 的并发中止是清理次生事件。解析结果另存 `.local/controlled-positive-v2-20261107/old-failure-derived.json`，没有执行旧任务或改写旧事件。
