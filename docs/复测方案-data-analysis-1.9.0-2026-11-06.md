## 1. 为什么需要这些样本

当前评估器 `paired-task-v2` 先算各任务内的配对断言通过率差，再让各任务等权。95% Hoeffding 区间半径为：

```text
radius_pp = 100 × sqrt(2 × ln(40) / n)
```

其中 `n` 是独立计分任务数；增加断言、重复同题、把同一业务表拆成多个提问都不能增加 `n`。

| 假设最终观测的任务等权增益 | 要让区间下界严格 > 0 的最少独立任务 |
| --- | ---: |
| +60pp | 21 |
| +50pp | 30 |
| +40pp | 47 |
| +37.19697pp | 54 |
| +30pp | 82 |
| +10pp | 738 |

历史 11-01 原版摘要能描述出约 +37.20pp 的任务等权差，但缺少运行期身份及原始证据，且旧题已经公开，**不能把它当作新留出题的效应预测或功效估计**。60 题是针对约 35–40pp 大效应的最小实用提案：其半径为 **35.06603pp**；54 题在上述历史点值下仅勉强越线，60 题留少量余量。48 题半径为 39.20501pp，可能无法支持约 37pp 的观测增益。

不存在脱离效应大小的唯一“最少题数”。这里的数字是给定观测差时的过线条件，**不是 80%/90% 统计功效承诺**。如果实际增益只有 10–30pp，这轮仍可能 `inconclusive`。不降低现行阈值，不在看到结果后从 48 加到 60 或继续加题直到通过。

`repeat=1` 是本方案明确选择的节省项，低于仓库默认的 3 次；同题内的随机波动尚未测量。若执行前决定要求重复稳定性，需重新冻结 `repeat=3`，主实验会话数由 512 增至 1,536，加同样的 8 次合成校验后为 1,544；独立 `n` 仍是 60。

## 3. 独立任务与真值

新增私有留出套件，拟标识 `data-analysis-1.9.0-holdout-v1`；目前尚未编写题目或产生 suiteHash。60 个计分任务建议分配如下：

| 场景 | 独立任务数 | 主要观察点 |
| --- | ---: | --- |
| 单 KPI 与指标口径 | 8 | 成交笔数与客流、未知分母、零基期、直答是否有可比基准 |
| 时间可比性 | 8 | 月长、未完期间、按日对齐后方向反转、不可合法对齐 |
| 加权与结构 | 8 | 不等组量、平均的平均、结构变化、权重缺失、不同率分母 |
| 指标拆解 | 8 | 两/三因子、成本负项、近零总变动、贡献值与闭合误差 |
| 异常判断 | 7 | 小样本、IQR 为零、真实异常与录入错误、不得随意删除 |
| 趋势与相关 | 7 | 点数不足、离群影响、弱趋势、相关不当因果、定义变更 |
| 数据质量 | 7 | 重复行、主键冲突、缺月、百分数尺度、总计行、可见 JOIN 行数异常 |
| 完整分析与证据边界 | 7 | 正式汇报、目标缺失、预测依据不足、算术自洽但口径可疑 |
| **合计** | **60** | 每个独立任务在 CLI 中只对应一个计分 taskId |

每题都要有数据来源/独立生成过程、datasetId、lineage、clusterId、主要失效机制和未使用旧算例的审阅记录。禁止同一数据集的归因题、直答题、对抗提问分别计为独立样本；同模板换数字也不自动增加独立性。相关子题合并到一个任务簇后再冻结，不能靠不同 taskId 让当前实现误计。凑不齐 60 个合格独立簇时，先修订设计，不能带虚增的 `n` 开跑。

旧 `suites/data-analysis-v2.json`、skill 自带样例、公开报告与脚本自测材料仅留作离线开发校验，不进入新留出集或正式分母。旧 suite 还存在与当前契约不一致的判据：例如当前允许有假设、基准和过程的测算，不能一概要求拒绝任何预测；销售额÷客流应按人均消费命名，不能奖励错误的“客单价”措辞。

另设 4 个 `kind: diagnostic, shouldActivate: false` 无关任务：普通翻译、纯文本校对、通用代码解释、无业务数据的行程整理。它们进入运行完整性和误触发检查，不进入主增益/胜率分母。4 次下误触发 ≤20% 实际要求 **0/4**；这只是小样本哨兵，不能据此声称总体误触发率已被精确约束到 20% 以下。

真值先于任何模型输出完成：使用独立 Decimal/精确运算，不以候选 `calc.py` 或 `quality_check.py` 作为唯一答案；公式、单位、分母、期间、舍入点与容差经第二次独立审阅。例：金额/单价容差 0.01，百分点容差 0.01pp，拆解同时校验各项贡献及总变动，具体值逐题冻结。正则须能区分正确结论、引用错误答案与否定句，不能仅搜索一个数字或“闭合”二字。

正式断言检验两侧共同承担的业务正确性与行为边界。六段标题、固定“输出形态”措辞、是否调用候选自带脚本属于次级契约取证，**不混入主增益断言**，否则会因 baseline 没有候选格式/文件而人为提高增益。主观察面固定为最终回答正文；文件只作副本和工具取证，不事后从回答切换到某个更优的报告文件。无法用现有断言可靠判定的语义交给盲评，不能为了凑题数加入恒真断言。

## 4. 正控、阴性对照与唯一变量

| 符号 | 配置 | 作用 |
| --- | --- | --- |
| B | `--no-skills`，不传任何 skill | 测量模型自身能力；两次主 run 各有独立 baseline |
| V | `--no-skills` + 仅显式加载六文件原版快照 | 主实验处理组；其有效性正是未知量 |
| C | `--no-skills` + 仅显式加载单独的行为消融包 | 阴性对照，检查移除行为契约后增益是否回落 |
| P | 独立 synthetic skill + 两个已知动作任务，另有无 skill baseline | 阳性链路校验，不计入候选有效性 |

主 run 为 **B↔V** 与 **B↔C**，各跑相同 64 题；当前 CLI 为两臂实现，`verify` 也要求每份 summary 有唯一被测 variant，因此不假设三臂或共享 baseline 能力。

C 在新的目录生成：使用 `stripBehavioralContract` 保留 V 完全相同的 frontmatter，正文为中性桩，**不复制可达的 scripts/references，也不链接回原包**。目录结构、可用通用工具、输入和工作区权限同其他组；C 和 B 仍可用系统 Python 完成计算。仅剥离 SKILL 正文但保留行为脚本/方法库，不能视为干净消融。

原 description 本身含有行为性要求，因此 C 是“保留触发描述的消融”，不是完全无信息的空 skill。需把这种残余写入报告；它可能令 C 仍有增益。也不能利用脚本缺失制造工具错误、超时或人为扣分来证明阴性成立：C 必须正常完成任务，且不以调用 V 专属脚本作为主断言。C 激活不足、输出不完整或仍有 ≥10pp 增益时，这次控制不成立/未区分，不能拿来支持候选。

P 单独冻结两个校准任务（例如触发词驱动的确定性 JSON 合同、系统 Python 对输入值计算并回传校验值），隐藏断言预先规定输出/动作。先以固定正确/错误产物做零 Provider 的断言及方向回放，再在未来获准执行时跑一次真实两臂小批。预期证据是 P 侧 2/2 成功读取、动作与真值均正确，且至少一个植入行为能被 baseline 对照和匿名正反序评委检出；不得要求这两题达到主评估器的最少 4 对或显著性门槛。若 baseline 也完全满足、没有预期差异、盲评反向或漏取证，暂停主实验并另记原因，不能重写校准答案刷通过。P 仅证明人工植入差异的链路可观测，不证明 data-analysis 有用。

每对两侧的模型、任务、CSV、上下文、通用工具、超时和目录结构一致，只有加载的 skill 不同。当前 CLI 创建空工作区，没有自动分发 CSV 附件的参数；本最小方案选择把公开 CSV 原文内联到同一任务 prompt，明确要求两侧原样落盘到相同的 `020_clean/` 路径，输出区同为 `060_reports/`。落盘错误保留为任务表现，不由人工给其中一组补材料；不假设存在尚未实现的附件预置功能。独立会话不继承其他输出；两个主 run 尽量相邻执行并记录时序，第二份 baseline 不是重复使用第一份输出。当前 CLI 的执行顺序不保证随机化，应把期间服务漂移作为限制记录。

## 5. 隔离、激活与独立评委

正式启动前验证 macOS `sandbox-exec` 以及每次启动的读写探针；不允许回退到无隔离。两侧可读同一份公开任务材料与本侧工作区；V 额外只读自身冻结包。私有真值、断言、expectedPoints、历史 runs/报告、其他组输出、源归档目录和其他技能均不可读。P、C 各仅可读自己的包。不能以“文件夹分开”代替实际权限探针。

主实验设置 `--no-keyword-signal`，激活只认可成功的目标包文件读取事件，保留开始/完成/错误证据及实际路径；模型声称读过或输出关键词不算成功激活。读取包是激活证据，成功执行并使用脚本结果是另一项合规证据，两者分开。

评委使用独立模型与独立新会话，只看到任务、私有预期要点、评分标准、匿名 A/B 输出；沿用并冻结现有来源词匿名化与头尾窗口算法，另存完整原文及评委实际可见文本。事先冻结随机种子及正反展示计划，每对两轮、两个方向各一次；保留全部 `judgeRuns`、展示顺序、标签语义、解析结果、错误和多数票。两轮分歧按现行规则聚合，不临时加第三票；缺票按现行法定轮数处理，不能挑票。不得把 skill 名称、包路径、组别标签塞入评委上下文；若既有匿名化后仍明显泄露来源，记录盲态受损，不临时发明改写规则或伪称严格盲评。报告也披露截断可能遗漏中段的限制。

## 6. 冻结判定标准与停止条件

沿用当前 `paired-task-v2`，不为这次复测修改代码或放宽阈值：

| 项目 | 本轮规则 |
| --- | --- |
| 身份/隔离 | manifest、包身份、原始产物完整性与实际隔离均验证通过，无污染 |
| 完整配对 | 60 个预定计分 pair 全部成功且断言覆盖一致；任一 baseline/V 失败，正式 gain 为 null |
| 主增益 | 任务等权配对增益 ≥10pp，95% Hoeffding 下界严格 >0；n=60 时实际还要求观测差 >35.06603pp |
| 激活 | V 正向 ≥60%（至少 36/60），≥80% 另标充分；误触发 0/4 |
| 评判覆盖 | 计分有效判定 ≥70%（至少 42/60），有效判定对 ≥4；仍保留未判定和失败分母 |
| 胜率 | 原始、超时惩罚、规则纠偏三个胜率通常均 ≥60%；客观增益 ≥20pp 且区间下界 >0 时现行门槛为 ≥50% |
| 全样本守门 | `wins / 60 ≥50%`；这是把所有预定计分对放进分母的比率，不是 Wilson 置信下界 |
| 超时与批次 | 通用 skill 超时上限为 20%，但本轮完整增益和 verify 更严格：包括诊断题在内两个主 run 必须全部成功，实际要求 0 被评失败/超时 |
| 成本 | 输出 token/耗时倍率及单位增益成本；`expensive` 可与有效并存，`runaway` 阻止有效结论 |
| 阴性元评估 | 两 run 的 task/suiteHash、model/judgeModel/repeat/judgeRepeat、断言等一致，身份隔离完整；V 增益 ≥10pp、C 增益 <10pp、C 正向激活 ≥60%、0 假阳性断言，实际用新版 CLI `verify` 重验 |

规则与评委冲突按规则优先并逐项披露；评委质量高不能替代缺失的完整配对/身份。C 增益 <10pp 是现有控制门槛，不是“真实效应等价于零”的统计证明，C 自己的区间也需公开。V 的综合有效结论与阴性元评估结果分别报告，任一控制/证据缺口不得被另一个 PASS 抹掉。

固定被评会话超时 `480000ms`、评委 `300000ms`；不调用 `--llm-advice`，不自动 archive。失败、预算暂停、访问探针拒绝均留档，不改为空字符串的通过；不补跑单个失败来拼成干净批次。需要修订时保留整批，以新 run 关联原 run、原因和新冻结清单。证据不足报 `inconclusive`，效应未达标照实报，不选择性加题。
