## 失败处理与计分保持

中间工具错误、SDK 重试或压缩事件保留为观察记录。SDK 最终仍失败的样本与无法解析的评委票保留为失败数据，继续其余预定独立样本；不补同一个失败样本、不缩减评委轮数、不改变失败分母。Host 隔离、身份、IPC 或证据持久化故障仍停止整批。即使全部模型样本成功，最终账本持久化失败也保持 `partial`，不能发布。

保留六项计分正确性修复：候选冻结身份、完整矩阵与缺失分母、访问隔离与激活取证、匿名成对评委及全部单次票、任务簇统计、阴性对照可比性。Agent 自主执行不改变规则优先、多数票、回归门禁或有效性标准。

- 原始事件逐条追加 JSONL；有内容的 1024 段 CJK 流生成 2068 条事件，写入 7,619,744 字节，逐条读回与全部收到的事件一致。

- 费用账本只追加被改动的 session/request/state 行；完整 JSON 仅初始化与终态生成。5000 个模拟 HTTP 请求产生 10,003 行，累计写入 4,980,319 字节，终态 JSON 1,434,972 字节；逐行回放与终态一致。旧 writer 的 RED 使用计量 sink，未制造海量物理写盘。
- 写入、fsync、终态 rename 失败会阻止新派发并保留 Host 首因；失败终态不反复重新序列化全部账本。请求查询使用 Map，增量同步不扫描完整历史。

这些验证证明 Host 的外层追加写入随收到的证据体积增长，未声称消除 SDK 自身累计消息快照的增长。未真实生成到原生最大输出长度，最大规模输出的内存、CPU、磁盘负载仍未实测；不以此降低 token 上限或关闭思考。
